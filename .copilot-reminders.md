## Testing Protocol

**ALWAYS use `make run-tests` for running the full test suite.**

❌ NEVER run `pytest tests/` directly  
❌ NEVER run `python -m pytest tests/`  
✅ ALWAYS run `make run-tests` (uses parallel execution with pytest-xdist, ~3x faster)

### When to use what:

- **Full test suite**: `make run-tests` (or `make run-tests ARGS="-q"` for quiet)
- **Serial execution** (debugging): `make run-tests-serial`
- **Single test file**: `make run-test-file FILE=test_inferno.py`
- **With coverage**: `make coverage`

### Why this matters:

1. The Makefile configures parallel execution (`-n auto`) for 3x speedup
2. The user has explicitly told you this MULTIPLE times
3. Ignoring established workflows breaks trust
4. This project has Make targets for EVERYTHING—check the Makefile first!

## Default Workflow

1. Need to run something? → Check `make help` first
2. See if there's a Make target for it
3. Use the Make target (don't reinvent the wheel)
